1. Architectural Overview

This chapter documents the milestone wherein White-Caves-Frontend and White-Caves-Server operate as completely decoupled, sovereign, separately-run Node.js processes. Communication is cleanly routed over HTTP (/api) and WebSockets (/socket.io) through Vite's high-speed dev reverse proxy, eradicating CORS bottlenecks and eliminating mock fallbacks in favor of live data.

2. Vault Configuration & Environment Separation

All sensitive credentials are maintained in the git-ignored secrets/ root vault. Neither the frontend nor backend checks credentials into source control.

Target Environment Key Variables Injected Sovereign Role
White-Caves-Server/.env PORT=5001, DATABASE_URL, MONGODB_URI, JWT_SECRET, DEV_AUTH_BYPASS Direct database connection, REST API routing, and Socket.IO initialization.
White-Caves-Frontend/.env.local VITE_API_URL=/api, VITE_FIREBASE_PROJECT_ID, VITE_STRIPE_PUBLIC_KEY Client-side proxy target, ensuring browser requests resolve without cross-origin blocks.
Why Relative Path VITE_API_URL=/api?
By utilizing relative paths, the browser issues requests directly to localhost:3000/api/.... Vite's internal development proxy intercepts and forwards payloads to http://127.0.0.1:5001 server-side, eliminating browser-level preflight CORS complications.
